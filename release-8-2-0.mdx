## Replacement README Text

### MFi Authentication

CarPlay requires the accessory to authenticate against the phone using an Apple **MFi authentication coprocessor**. This is a hardware chip, it cannot be emulated in software, and LIVI does not ship or bypass it. You need a physical coprocessor (e.g. salvaged from a certified CarPlay accessory or sourced as a module) wired to the I²C bus of your board.

LIVI talks to the chip directly. Configuration (`config.json`):

| Key | Default | Description |
| --- | --- | --- |
| `carPlayMfiI2cBus` | `2` | I²C bus number the coprocessor is on |
| `carPlayMfiPowerGpio` | `-1` | GPIO that powers the coprocessor; `-1` means no power pin and requires an externally powered chip |

With `carPlayMfiPowerGpio` set to `-1`, LIVI skips GPIO power control and expects the chip to be powered externally. If your board powers the chip through a GPIO, set the pin to match your wiring.

When MFi setup is enabled in the installer, it seeds bus `2` if missing and GPIO `21` when the saved power pin is missing, null, empty, or `-1`. Other saved pin values are preserved. The application default and installer-seeded configuration are therefore different.

Back up and validate your configuration before rerunning MFi setup. An unreadable or invalid JSON configuration is replaced from an empty object, and an intentional external-power value of `-1` is replaced with the installer pin.

Without a coprocessor, native CarPlay is unavailable. Dongle-based CarPlay and all Android Auto paths work regardless.

## Additions to Existing README Sections

### Desktop and Headless

Add this shared installer note without replacing either installation flow:

Both installers configure NetworkManager with optional Wi-Fi Protected Management Frames by writing `/etc/NetworkManager/conf.d/99-LIVI-wifi-pmf.conf`:

```ini NetworkManager PMF configuration
[connection]
wifi-sec.pmf=2
```

This is a host-wide NetworkManager setting, not a LIVI-only access-point option. The installer attempts to reload NetworkManager configuration when `nmcli` is available; a successful reload is not guaranteed by the script.

When run from a checkout containing the display assets, installation prefers those local display profiles and HDMI setup assets before falling back to packaged or repository sources.

### View and Safe Area

Add after the existing main and cluster examples:

If both `projectionWidth` and `projectionHeight` are absent from the saved configuration, LIVI tries to use panel EDID dimensions as the defaults for projection and cluster resolution. Setting either projection dimension skips this default lookup; it does not reset explicitly saved settings.

On Linux, lookup uses a connected output matching the connector in `drm.edid_firmware`, or the sole connected output. Missing, invalid, or ambiguous EDID data produces no detected geometry. The first lookup result, including failure, is cached for the process lifetime.

Main-stream width and height passed by the CarPlay and Android Auto paths are rounded down to even values. The diff does not establish equivalent new rounding for every cluster-stream path.

### Small Displays and Settings

Add near the existing small-display description:

For positive window content heights below 292 pixels, LIVI multiplies your configured UI zoom by `height / 292`. At 292 pixels or above, the configured zoom is unchanged by this height multiplier. The change is applied during window creation and settings saving; automatic handling of every resize is not established by the diff.

Settings pages now scroll their headers together with grouped rows. Camera selection uses a list: selecting a valid device saves it and returns to the previous page. Calibration sliders snap values to the configured step precision.

### Phone Time at CarPlay Connection

Add as a short subsection under Native Apple CarPlay:

LIVI handles a phone time update once per peer connection. If the supplied time differs from the host by more than 10 seconds, it attempts to set the UTC system clock and save it with `fake-hwclock`. Errors are logged. This requires suitable host permissions and tools; the change alone does not confirm that every installation can set its clock. Timezone and daylight-saving fields from this message are not applied by the shown handler.

### Raspberry Pi HDMI-PR Displays

Add under Installation for hosts using the HDMI-PR setup script:

`scripts/install/pi/setup-hdmi-pr-display.sh` accepts `--kernel` to prepare a target kernel. Apt-managed Raspberry Pi kernels use matching package sources; the custom-kernel fallback is limited to the running kernel.

Setup installs `/etc/kernel/postinst.d/livi-vc4` and `/usr/local/lib/livi/setup-hdmi-pr-display.sh` so the patch can be rebuilt after a kernel installation. A failed hook creates `/var/lib/livi/hdmi-pr/BUILD-FAILED-<kernel-version>` and warns that the display may remain dark. The hook still exits successfully, so a completed package installation does not prove the display patch succeeded.

Do not reboot into that kernel until the failure is resolved. Retry the installed setup script against the affected version:

```bash Retry a failed HDMI-PR build
sudo /usr/local/lib/livi/setup-hdmi-pr-display.sh --kernel '<kernel-version>'
```

The script checks module vermagic before installation, preserves a module backup, and adds an initramfs hook for EDID firmware. Where `update-initramfs` is available, it attempts an initramfs update.

Three Mercedes/Volvo EDID assets changed, but the supplied diff contains no binary timing details. Do not claim specific new display modes or dimensions from those binary changes.
