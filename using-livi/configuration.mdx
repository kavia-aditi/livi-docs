LIVI stores all persistent settings in a single JSON config file. You can change most values through the in-app Settings pages, and some values are applied immediately while others require a reconnect or restart. This page explains where the file lives, how to edit it, and what each setting controls.

## Config file location

LIVI looks for `config.json` in the platform-specific user data directory. The path is determined in `native/livi-helperd/bin/livi-core/src/paths.rs`.

### Linux

```text
$XDG_CONFIG_HOME/LIVI/config.json
```

If `XDG_CONFIG_HOME` is not set or empty, it falls back to:

```text
~/.config/LIVI/config.json
```

The config backup mirror is written to:

```text
$XDG_DATA_HOME/LIVI/config.json
```

If `XDG_DATA_HOME` is not set or empty, it falls back to:

```text
~/.local/share/LIVI/config.json
```

### macOS

```text
~/Library/Application Support/LIVI/config.json
```

The backup mirror is written to:

```text
~/Library/Application Support/LIVI/backup/config.json
```

### File format

The config file is standard JSON. LIVI validates the file on load and silently corrects or falls back to defaults for fields with the wrong type. Unknown keys are preserved but not used. Empty icon fields (`carplayIcon120`, `carplayIcon180`, `carplayIcon256`) are omitted from the file when blank.

## Apply, reconnect, and restart behavior

Not every setting takes effect the moment you change it. LIVI distinguishes three behaviors:

- **Apply immediately** : the change is sent to the running core and takes effect at once
- **Reconnect only** : the change requires disconnecting and reconnecting the phone session
- **Restart required** : the change needs a full application restart

## Editing the config file

You can edit `config.json` while LIVI is not running. On the next start, LIVI loads the file, validates every field against its type, and silently replaces malformed values with defaults. If the file is corrupted, LIVI restores from the backup mirror.

To edit while LIVI is running, change the value through the Settings UI. The UI sends a patch to the core, which validates it, writes the file atomically, and updates both the primary and backup copies.

## Validation rules

The core applies a few hard rules when saving:

- `wifiPassword` must be 8 to 63 characters, inclusive. A shorter or longer value falls back to the default `"12345678"`.
- Unknown keys are accepted but ignored by the core.
- Type mismatches fall back to defaults per field.
- Icon fields are omitted from the file when empty.
- `lastKnownGps` is kept when present.

## Window bounds

Screen position and size are stored in `mainScreenBounds`, `dashScreenBounds`, and `auxScreenBounds` as `{ x, y, width, height }`. These are set automatically when you move or resize a window and are not exposed in the settings UI.
